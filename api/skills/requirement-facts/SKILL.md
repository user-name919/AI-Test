# 需求事实提取

用途：从企业需求、技术方案及补充材料抽取可追溯业务规则。这是平台方法指导，不替代人工作出业务决定。

1. 先区分角色、输入条件、操作、状态变化和预期结果，避免把实现方式当作已确认产品要求。
2. 明文事实使用 explicit；合理猜测使用 inferred；材料缺失或冲突使用 unresolved，并建立问题。不得把推断升级成明文事实。
3. 每条明文事实必须引用文档 ID、块 ID 和完整摘录。不要只因材料含有一个关键词，就声称支持更具体的规则。
4. 两份材料冲突时保留双方来源及各自适用条件，询问谁来确认；文件顺序、文件名或技术文档角色均不是覆盖权限。
5. 对图片、扫描件、复杂表格的提取警告保持可见。不通过标题猜测未识别内容。
6. 不规定固定用例数量；事实数量取决于材料，不为凑数编造边界、权限或数据。
7. 下游覆盖分析必须区分已纳入范围的显式事实、推断和排除项。不能将“已处理文档块”解释为“业务规则已全部正确识别”。

结合 references/examples.md 中的缺失信息与冲突例子；输出格式由当前阶段的 JSON 契约决定。
