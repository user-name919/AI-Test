# 用例质量审查

用途：给出可复核的质量问题，不能代替人工审核或产品测试结果。

1. 检查事实依据和引用是否足以支撑每条步骤/预期；代码已验证引用存在，也不代表语义一定成立。
2. 检查前置条件、角色、测试数据来源、可观察断言、状态变化和失败分支；缺少信息应指出，不自动补造。
3. 对重复用例、步骤矛盾、不可执行前置、不可观察结果、遗漏显式规则分别给出问题，并关联目标 ID 与依据。
4. 浏览器不能验证的服务端计算或后台状态，标记 API 或人工验证，不宣称 Playwright 可以直接证明。
5. 审查建议不改写人工最终口径；严重问题与待确认事项应阻止相关用例发布，或者由人工明确排除并写理由。
6. 不使用一个平均分掩盖严重语义错误；逐问题说明影响与建议，保留检查者为 model。
