## 已确认的范围

- 两个核心入口：需求驱动自动化测试、代码变更驱动回归；用例审核、环境、执行、报告共用。
- 回归只读取本机已有 Git 对象；用户部署测试环境，平台不自动部署、不拉取远端 PR。
- 目标分支不是当前分支时，用平台管理的独立 worktree 读取；不切换用户原工作区，不修改 lvworkbench。
- 多条相关用例共享当前浏览器与登录态。逐条记录结果，普通失败或受阻后继续；会话无法继续时停止。
- AI 可基于 DOM 与局部源码选择动作和数据；人工最终口径是执行依据；源码事实不能直接证明页面通过。
- 仓库使用根目录 web/、api/、packages/contracts/，采用 pnpm workspace。
- 当前不做敏感信息检测与脱敏、多 Agent、跨项目 Manifest 发布；保留必要的密钥不入库、文件访问边界和受控动作规则。
- 以相关模块检查和关键人工验收为主，不要求每个任务都执行全项目严格回归。

## 发给普通模型的执行说明

复制以下指令，替换任务编号和实际工作目录：

```text
只执行 docs/后续建设计划/02-分阶段开发任务.md 中的任务 Txx。
先读 00、01 和 Txx 的依赖产物，核对工作目录、分支、git status。
用户授权的是该任务范围，禁止顺便重写相邻功能或切换被测项目分支。
核对前置任务已经交付；若接口与文档不一致，先列出实际差异，不虚构实现。
按指定接口与页面行为实现，保留既有数据与行为；不要将历史报告重算为当前口径。
执行任务规定的最小验证，不默认跑全仓库严格回归。
完成后记录修改文件、验证结果、遗留问题和 commit SHA。
仅提交本任务文件，不纳入登录态、数据库、Trace、密钥或他人的改动。
若依赖导致任务过大，将子任务清单写入交接记录，完成一个可验收切片后再继续。
```

每个任务使用独立提交；创建 `docs/后续建设计划/交接记录.md` 追加实际状态。任务未完成不得标完成，不以“类型检查通过”替代业务验收。首轮执行按 T00 → T01 → T02 顺序，负责人验收页面骨架后再进入后续任务。
